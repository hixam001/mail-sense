# MailSense interface

This is an Operate surface for a laptop under classroom lighting. Light blue
work areas keep dense numbers readable; deep atlas-blue navigation anchors every
page. Teal identifies ham, burnt orange identifies spam, always with text labels.
This direction is an autonomous implementation choice under the user's delivery
instruction, not a claimed human design approval.

Use the system UI sans stack, tabular measurements and monospace only for hashes
or formulas. Titles are 28–34 px, body 16 px, secondary text 14 px. Use an
8/12/16/24/32 px spacing rhythm, full subtle borders, white 12 px-radius analysis
panels, native controls and visible blue focus outlines. No remote fonts/images.
Tables and paired comparison areas carry the content.

The signature interaction is a labeled class-balance band changing with dataset
scope and real counts. Only that band animates width; reduced-motion removes it.
Charts have text/table equivalents. Loading and errors replace old results.

A 232 px desktop rail sits beside a header and bounded work area. Mobile
navigation becomes a horizontal scrolling row; paired areas stack and tables
scroll inside labeled containers. Use skip navigation, semantic landmarks,
active-route labels and explicit units. Future modules inherit this system.

Keyboard submission focuses the result heading; token inspection focuses its new section. Active mobile navigation stays visible across route and viewport changes. Prediction labels its frozen training source; Evaluation labels its held-out test source. Mobile comparison metrics and confusion matrices fit without horizontal scrolling. General wide tables remain keyboard-scrollable.
